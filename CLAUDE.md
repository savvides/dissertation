# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This repository contains Philippos Savvides's 2018 PhD dissertation from Arizona State University: "Teaching Science Lab Safety: Are Virtual Simulations Effective?" The study investigated VR/desktop/video immersion levels (n=108) on knowledge, cognitive load, and presence for lab safety training.

## Repository Structure

- `Savvides_asu_0010E_18427.pdf` — Original dissertation PDF (source of truth for figures and formatting)
- `dissertation.md` — Full markdown conversion with an "Updated Literature Review (2019-2026)" addendum section
- `data.csv` — De-identified study data (n=108): learning gains, condition, presence, cognitive load
- `litreview.csv` — Consensus search export (249 rows; 219 unique papers published 2021–2025)
- `README.md` — Project overview, study summary, literature review addendum summary, and methodological retrospective
- `HOW-IT-WAS-MADE.md` — Process write-up explaining how the interactive site was built with Claude Code
- `CHANGELOG.md` — Versioned release notes for the interactive site (Keep a Changelog format, SemVer)
- `index.html` / `style.css` / `script.js` — Single-page interactive scrollytelling site in the "Newsroom" design (D3.js v7, vanilla CSS, classic scripts, no build tools). Sections: hero with a participant strip (`#hero`), scroll-driven narrative with a sticky chart (`#story`), personal coda (`#coda`), interactive Evidence Lab (`#lab`), and portfolio footer (`#about`). `script.js` must not throw when `window.d3` is missing, and every number it shows comes from `window.STUDY`.
- `data.js` — Generated from `data.csv`: `window.STUDY` with the points, labels and precomputed statistics. **Never hand-edit it.** Change `data.csv` or `scripts/csv_to_js.js`, then run `node scripts/csv_to_js.js` (or `npm run data`); a test fails if `data.js` is stale.
- `vendor/` — `d3.v7.9.0.min.js` (self-hosted, byte-identical to jsDelivr's `d3@7.9.0/dist/d3.min.js`) and its ISC license
- `scripts/csv_to_js.js` — The generator for `data.js`
- `scripts/screenshots.js` — Renders `docs/screenshot.png` (1440×900) and `docs/social-preview.png` (1200×630) at step 4; rerun it after visual changes
- `package.json` / `package-lock.json` / `playwright.config.js` — Dev-only tooling (Playwright 1.64.0 and axe-core), nothing the site loads
- `tests/` — Playwright suite: narrative steps, layout and overflow, resize, interrupted transitions, the Lab (keyboard and readout), axe-core, contrast and color-vision checks, d3-unavailable and `file://` resilience, content regression, data freshness, and release hygiene (docs, CI, dead-code sweep). `tests/serve.js` is the dependency-free static server it starts.
- `LICENSE` — CC BY 4.0
- `docs/` — README screenshot and social preview image (regenerated by `scripts/screenshots.js`)
- `.github/workflows/` — `ci.yml` (vnu HTML validation, lychee link check, Playwright `test` job) and `deploy.yml` (GitHub Pages, runs after CI passes)

## Commands

- `npm ci` — install the dev tooling (once per checkout)
- `npx playwright install chromium webkit` — download the test browsers (once)
- `npx playwright test` — run the whole suite (Chromium and WebKit at six viewports, plus a `file://` project). Run it before every commit that touches the site.
- `npx playwright test tests/lab.spec.js --project=chromium-1440x900` — one file in one project
- `node scripts/csv_to_js.js` — regenerate `data.js` after `data.csv` changes
- `node scripts/screenshots.js` — regenerate the two docs images
- `node tests/serve.js` — preview the site at http://localhost:4173 (the suite reuses this server if it's already running)

## Key Context

- Never hand-edit `data.js`; it is generated from `data.csv` (see Commands). The page shows only numbers that come from `window.STUDY`
- Test tags (see `playwright.config.js`): tag pure-Node tests `@once` so they run in one project, not 12; `@file` tests run only in `file-chromium`
- `tests/repo.spec.js` runs a dead-code sweep: every CSS selector must appear in `index.html` or `script.js`, and every `script.js` function must be referenced. Remove markup, CSS and JS together
- `tests/repo.spec.js` also pins docs content: the README version badge, the CHANGELOG entry and compare link, and required strings in this file. A version bump means updating that test too
- The original dissertation was published December 2018; all original citations are pre-2019
- The markdown version preserves the original text verbatim; new content goes only in the addendum section
- A 2026 reanalysis found the presence-learning correlation is an ecological fallacy (significant overall, non-significant within conditions) — the README retrospective documents this
- Figures are referenced but not embedded — they live in the original PDF
- Citation style is APA 6th edition throughout
- The "Updated Literature Review (2019-2026)" addendum is organized to mirror the original literature review subsections: Simulations and Educational Virtual Environments; Applications of VR in Science Education; Immersion and Presence; Embodied Cognition; Constructivism and Problem-based Learning; Cognitive Load Theory

## Working with the Addendum

When adding new literature to the addendum section:
- Place content under the matching subsection heading
- Use APA 6th edition citation format consistent with the References section
- Add new references to the References section in alphabetical order
- Note whether new findings confirm, contradict, or extend the 2018 study results
